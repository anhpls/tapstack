## Cards and the stack

| Feature | Status | Why it matters |
| --- | --- | --- |
| Card stack | ✅ Done | One home for every membership, so nobody digs through apps or a wallet at the register. |
| Category stacks | ✅ Done | Keeps the home screen short as cards pile up; one tap fans a category open. |
| "Almost there" section | ✅ Done | Puts cards one visit from a reward on top, which nudges the visit that earns it. |
| Search | ✅ Done | Finds any card in a second at checkout. |
| Card detail with barcode | ✅ Done | A real Code128 barcode, so any store scanner reads it with no new hardware. |
| Smooth auto-brightness | ✅ Done | Dim screens fail at older scanners; it brightens gently and restores after, like a boarding pass. |
| Stamp history | ✅ Done | Customers trust what they can see; corrections show only as a net daily change. |
| Refresh button in the card | ✅ Done | Updates stamps without fighting the swipe-to-close gesture. |
| Premium card finish | ✅ Done | Sheen, bright edge and soft shadow make cards feel like objects worth keeping. |
| "Here now" and "Recent" sections | ⬜ Not started | The card for the shop you're in, or were just in, is always one tap away. |
| Custom stacks | ⬜ Not started | Lets people group cards their own way, like "Near campus" or "Date spots". |
| Tilt-and-shine and card flip | ⬜ Not started | Light that moves as the phone tilts makes a digital card feel physical. |
| Stamp-press animation and reward celebration | ⬜ Not started | A small moment of delight at every stamp keeps people coming back. |
| Official card art | ⬜ Not started | When a shop claims its page, its high-res art replaces customers' scans for everyone. |

## Stamps, rewards and trust

| Feature | Status | Why it matters |
| --- | --- | --- |
| Staff-only stamping | ✅ Done | Stamps only count when the shop gives them, never from a photo or a self-tap. |
| Multi-stamp visits with a per-visit limit | ✅ Done | Handles three drinks in one tap while capping abuse. |
| Stamp promos (double stamps) | ✅ Done | Shops run "double stamp weekend" once; the bonus applies automatically. |
| Two-minute cooldown | ✅ Done | Stops double taps and repeat stamping; corrections don't trigger it. |
| Customer-started redemption with a live code | ✅ Done | The customer shows a 4-digit code and a ticking timer that a screenshot can't fake; staff confirm. |
| Carryover of extra stamps | ✅ Done | Stamps beyond the reward are never lost. |
| Two-way corrections with a double-tap guard | ✅ Done | Managers fix mistakes in either direction without faking purchases or promo bonuses. |
| Every stamp logged (who, when, why) | ✅ Done | An honest history powers fraud checks, staff logs and promo results. |
| Test shops | ✅ Done | One person can test as both customer and staff; real shops keep every rule. |
| Paper-transfer policy (honor all, cap, or fresh start with bonus) | ⬜ Not started | Each shop decides how much of the paper card it trusts. |
| Sign-up bonus | ⬜ Not started | A free stamp on joining gives people a reason to sign up at the counter. |
| Fraud alerts | ⬜ Not started | Flags unusual patterns and obviously edited scans before they cost the shop. |
| Smart checkout assistant | ⬜ Not started | Says which reward to use now, values points in dollars, and warns before points expire. |
| Expiring-reward reminders | ⬜ Not started | Earned rewards get used instead of silently expiring. |

## Accounts, security and privacy

| Feature | Status | Why it matters |
| --- | --- | --- |
| Passwordless email-code sign-in | ✅ Done | No password to forget or leak; signing up and signing in are the same step. |
| One account, two modes | ✅ Done | Customers and staff use the same login; roles decide what each person sees. |
| Row Level Security on every table | ✅ Done | The database itself only shows each person their own data, even if the app has a bug. |
| Protected database functions for sensitive actions | ✅ Done | Stamps, rewards and transfers can only happen after the rules are checked. |
| Secrets kept out of git | ✅ Done | API keys never reach GitHub. |
| Sequential member numbers | ✅ Done | No collisions ever; a number identifies a card but unlocks nothing. |
| Sign in with Apple | ⬜ Not started | One tap with Face ID, the most popular option on iPhone. Needs the $99 account. |
| Face ID app lock | ⬜ Not started | Keeps cards private if someone else picks up the phone. |
| Tapstack email domain (Resend) | ⬜ Not started | Codes come from Tapstack, not a personal Gmail, and land in inboxes instead of spam. |
| Privacy policy, terms and support page | ⬜ Not started | Required by the App Store and by California privacy law (CCPA). |
| Security review before launch | ⬜ Not started | Checks every table, function and secret before real people's data is in it. |
